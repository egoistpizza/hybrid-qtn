# Hybrid QTN: Memory-Efficient Image Segmentation using Matrix Product States

This repository contains the research codebase for the Hybrid QTN project. 

## Overview
Dense image segmentation models like U-Net face significant memory constraints due to high-dimensional matrix multiplications in their deepest layers. This bottleneck limits their scalability on standard hardware.

We address this by integrating a Quantum-Inspired Tensor Network layer. By replacing the standard U-Net bottleneck with **Matrix Product States (MPS)**, we aim to substantially reduce the parameter count and VRAM usage while preserving the spatial correlations required for medical image segmentation. The architecture is benchmarked on the MedMNIST dataset.

## Core Methodology
* **Architecture Modification:** We remove the dense bottleneck layers of a standard U-Net and introduce a custom PyTorch-based MPS layer.
* **Tensor Decomposition:** Instead of computing large dense weight matrices, the MPS layer uses SVD to decompose high-rank tensors into a sequence of low-rank tensors.
* **Feature Preservation:** Truncating insignificant singular values compresses the parameter space, while the tensor network structure preserves the latent semantic features required for the decoder.

## Installation
Using a virtual environment is recommended to avoid dependency conflicts.

```bash
git clone https://github.com/egoistpizza/hybrid-qtn.git
cd hybrid-qtn

python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

pip install -r requirements.txt
```

> **Training on a GPU pod?** Do not use the commands above. `requirements.txt`
> pins a CUDA 13 build of PyTorch that cannot initialise on the driver most
> pods ship. See [GPU Pod Setup](#gpu-pod-setup-rtx-5090--blackwell) instead.

## GPU Pod Setup (RTX 5090 / Blackwell)

There are two shell files and they are **not** interchangeable. `setup_rtx5090_pod.sh`
is committed and runs once per machine; `env.cuda.sh` is *generated by* that script and
is sourced once per shell.

| File | Committed? | Run it | What it does |
| --- | --- | --- | --- |
| `scripts/setup_rtx5090_pod.sh` | yes | **once per pod** | Builds the venv, installs a driver-matched PyTorch, verifies GPU compute |
| `env.cuda.sh` | no — generated | **every new shell** | Activates the venv and exports CUDA tuning variables |

### Order of operations

**1. Provision the pod — once, on a fresh machine.**

```bash
./scripts/setup_rtx5090_pod.sh
```

This creates `venv/`, installs PyTorch built for your driver, installs project
dependencies, then runs a GPU self-test (matmul, AMP, cuDNN, `torch.compile`, and a
full-resolution forward pass through the model). It exits non-zero if any check fails,
so a clean exit means the environment is genuinely ready. It also writes `env.cuda.sh`
and a `requirements-cu128.lock.txt` snapshot.

Useful flags:

```bash
./scripts/setup_rtx5090_pod.sh --recreate     # rebuild the venv from scratch
./scripts/setup_rtx5090_pod.sh --with-onnx    # add ONNX extras, needed only for export.py
./scripts/setup_rtx5090_pod.sh --skip-verify  # install without the GPU self-test
```

**2. Open a shell — every time you reconnect.**

```bash
source env.cuda.sh
```

This activates the venv, so a separate `source venv/bin/activate` is redundant. If you
would rather not source anything, call the interpreter directly instead —
`venv/bin/python train.py ...` — and you simply forgo the tuning variables.

**3. Authenticate — once per pod, before the first run.**

`train.py` calls `wandb.init()` unconditionally and will block on an interactive prompt
if no credentials are present:

```bash
wandb login            # or: export WANDB_MODE=offline  to skip logging entirely
kaggle auth login      # only if you fetch datasets from Kaggle in step 4
```

**4. Fetch a dataset — once per dataset.**

```bash
python scripts/download_kvasir_seg.py
python scripts/download_cvc_clinicdb.py                                  # via Kaggle
python scripts/download_cvc_clinicdb.py --source local --archive path.zip  # from a local archive
```

Each writes under `data/` and skips work if the dataset is already present; pass
`--force` to re-download.

**5. Train.**

```bash
python train.py --model deep_hybrid --dataset kvasir_seg --bond_dim 32 --epochs 100
```

**6. Evaluate, and optionally export.**

```bash
python evaluate.py --model deep_hybrid --dataset kvasir_seg --bond_dim 32
python export.py   --model deep_hybrid --bond_dim 32      # requires --with-onnx in step 1
```

Steps 1, 3 and 4 are one-time per pod. Reconnecting later means step 2, then straight to
step 5.

### Why a dedicated setup script

The RTX 5090 is Blackwell (`sm_120`), and pods commonly ship NVIDIA driver r570, which
supports CUDA 12.8. PyTorch `cu130` wheels require driver r580 or newer and fail on r570
with a misleading error — the GPU is detected, `torch.cuda.device_count()` returns 1, but
initialisation dies:

```
CUDA initialization: The NVIDIA driver on your system is too old (found version 12080)
```

`requirements.txt` currently pins `torch==2.13.0` plus the `nvidia-*-cu13` stack, which
reproduces exactly that failure. The setup script filters those pins and installs
`torch==2.11.0+cu128` — the newest cu128 build, carrying native `sm_120` kernels and
running on r570 as well as newer drivers. It also pins `onnxruntime-gpu==1.26.0` under
`--with-onnx`, the last release built against CUDA 12.x.

Consequently, **do not run `pip install -r requirements.txt` inside a pod venv.** It will
silently undo the setup. Re-run the setup script instead.

## Estimated Parameter Overhead (Bottleneck)
| Layer                    | Formula                   |  r=32 |  r=64 | r=128 |
| ------------------------ | ------------------------- | ----: | ----: | ----: |
| Axial MPS (Ours)         | 2 × r⁴ + 2 × C × r        | 2.17M | 33.7M |  537M |
| Vanilla bottleneck       | 2 × Conv3×3 + 2 × BN      | 14.2M |     — |     — |

*Note: The exact measurable parameter count for the Axial MPS layer at r=32 is 2,167,840, reducing the Vanilla U-Net bottleneck overhead by approximately 85% without exceeding VRAM limits.*
